OneDS reference

OneDS is a shared plain HTML and CSS design system for building consistent interfaces without a runtime or dependency chain. This catalog documents the tokens and components that exist in the repository today.

Set up a new project

Link the library, keep the link out of version control, install the agent protocol, and reserve a local component directory.

Link OneDS

Run from the consuming project's root.

ln -s ~/Documents/SideProjects/oneds oneds

Ignore the symlink

Add this line to the consuming project's .gitignore.

/oneds

Install the agent protocol

Copy the repository instructions into the standard Copilot location.

mkdir -p .github
cp oneds/AGENT_PROTOCOL.md .github/copilot-instructions.md

Create the local component area

Keep unmatched application patterns separate from the shared library.

mkdir -p src/_local

How OneDS works day to day

The manifest is the routing layer between shared components and application-specific work.

Read the manifest

The agent reads oneds/MANIFEST.md before writing interface code and checks whether a matching component is already built.

Reuse the library

When a component matches, the agent copies the package from oneds/components/<name>/ verbatim.

Keep unmatched work local

When nothing matches, the agent builds in src/_local/ and adds an ONEDS-CANDIDATE marker describing the pattern and its purpose.

Run the checker

The checker rejects literal design values, undefined tokens, incomplete component packages, manifest drift, and inline style attributes.

Make a system change

Token source changes flow through generation and validation in a fixed order.

  1. Edit tokens/oneds.tokens.json, the token source of truth.
  2. Generate the CSS custom properties.
  3. Run the repository checks.
node scripts/build-tokens.mjs
node scripts/check.mjs

Do not edit tokens.css directly. It is generated from tokens/oneds.tokens.json and will be replaced by the next token build.
