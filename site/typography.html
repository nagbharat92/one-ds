Typography

OneDS uses a compact type system tuned for product interfaces, with separate family roles for reading and controls.

Font families

Both stacks prioritize Segoe Sans and fall back through platform Segoe UI faces to a generic sans serif.

Content family

--oneds-reference-font-family-content

Use for page titles, section headings, paragraphs, and other sustained reading.

"Segoe Sans", "Segoe UI Variable Text", "Segoe UI", sans-serif

Functional family

--oneds-reference-font-family-functional

Use for controls, labels, token names, compact metadata, and operational text.

"Segoe Sans", "Segoe UI Variable Small", "Segoe UI", sans-serif

Line height and letter spacing

Line-height tokens move from compact headings to relaxed reading. Letter spacing remains neutral throughout the system.

Tight rhythm keeps a short heading visually cohesive across two lines of text.

--oneds-reference-font-line-height-tight1.25

Snug rhythm gives supporting headings a little more room across two lines of text.

--oneds-reference-font-line-height-snug1.4

Normal rhythm supports interface copy that must remain compact and readable across two lines.

--oneds-reference-font-line-height-normal1.5

Relaxed rhythm is intended for longer passages where additional vertical space makes scanning easier.

--oneds-reference-font-line-height-relaxed1.65

OneDS preserves natural letter spacing instead of using an overline treatment.

--oneds-reference-font-letter-spacing0

Optical size and measure

Optical settings tune variable fonts for their role; the measure token limits long-form reading width.

Small optical setting for compact labels.

--oneds-reference-font-optical-small"opsz" 8

Text optical setting for body content.

--oneds-reference-font-optical-text"opsz" 14

Display optical setting for titles.

--oneds-reference-font-optical-display"opsz" 18

The readable measure limits sustained prose to a comfortable line length while allowing compact interface elements to size independently.

--oneds-reference-font-measure68ch

A stable vocabulary for product work

Tokens hold decisions; components turn those decisions into reusable behavior.

OneDS keeps the implementation close to the platform. Teams link plain CSS, choose an existing component when it fits, and keep application-specific patterns local until they prove reusable.

Reference note · Generated tokens are never edited by hand.
