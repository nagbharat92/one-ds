# OneDS generation rules

- **Required:** Read `oneds/MANIFEST.md` before writing any UI.
- **Required:** Copy a matching component from `oneds/components/<name>/` verbatim.
- **Required:** When a component is added to `oneds/components/`, its Status in `oneds/MANIFEST.md` must be updated to "built" in the same change. A component directory that exists while its manifest row says "not built" is a defect.
- **Required:** Give every `<table>` a bounded surface that owns its horizontal overflow, so a wide table scrolls inside its edge instead of stretching the page. Copy the shipped pattern from `oneds/components/data-table/data-table.html`: a `.card` wrapping a `.data-table__scroll` wrapping the `<table>`. A local wrapper that draws the same edge and sets `overflow-x: auto` on itself is equivalent, and must be declared with `ONEDS-CANDIDATE`.
- **Required:** Use only tokens defined in `oneds/tokens.css` for every color, spacing, and size value.
- **Required:** Use the neutral foreground ramp by role: `--oneds-color-foreground-neutral-primary` for body copy and headings, `--oneds-color-foreground-neutral-secondary` for supporting text and metadata, `--oneds-color-foreground-neutral-tertiary` for the quietest labels and placeholders. All three clear WCAG AA at 4.5:1 across every supported `groundLightness` in both light and dark.
- **Required:** Use the typography roles by intent: `--oneds-semantic-typography-functional-*` for product chrome (navigation, controls, labels) and `--oneds-semantic-typography-content-*` for material meant to be read. Each role pairs a size, a line height, and a letter spacing that share its suffix; take all three.
- **Required:** Size separates structural levels; colour separates primary from supporting text at the same level. A heading and the description directly beneath it are one level, so the description keeps the body size and normal leading and moves to `--oneds-color-foreground-neutral-secondary`. It never earns a size step of its own. Violation: `.section__description { font-size: var(--oneds-semantic-typography-functional-subtitle-size); color: var(--oneds-color-foreground-neutral-primary); }`. Correction: `.section__description { font-size: var(--oneds-semantic-typography-functional-body-large-size); color: var(--oneds-color-foreground-neutral-secondary); }`.
- **Required:** Choose a spacing token by the relationship between the two things it separates, never by a distance. The gap ladder is `--oneds-rhythm-tight` (parts fused into one object, such as an icon and its label), `--oneds-rhythm-group` (a label beside the control it names, where the control's own box supplies the breathing room), `--oneds-rhythm-items` (repeated equals in one set, such as chips or list rows, and any heading stacked above its own description), `--oneds-rhythm-component` (distinct siblings in one region, such as a table and the note beside it), `--oneds-rhythm-section` (a header and the content it introduces), `--oneds-rhythm-block` (page-level blocks), and `--oneds-rhythm-page` (the page's own top and bottom edge). Padding for a surface uses `--oneds-inset-tight` for a dense surface such as a table cell, `--oneds-inset-default` for a card or panel, and `--oneds-inset-loose` for a dialog or hero.
- **Required:** Every rule that sets a `font-size` sets the matching `line-height` beside it. A line height token resolves to a px length, so it inherits unchanged: a rule that resizes text without restating its line height keeps the ancestor's leading and the type collapses into itself. Violation: `.sidebar__link { font-size: var(--oneds-semantic-typography-functional-body-medium-size); }` — 14px text left on the 20px leading of whatever contains it. Correction: add `line-height: var(--oneds-semantic-typography-functional-body-medium-line-height);` to the same rule.
- **Required:** A text box is exactly its line height tall and nothing is trimmed, so the leading inside the type is added to whatever gap token separates it from the next block. Choose the gap for how the pair should read, then leave it alone; never add or remove space to compensate for a line height, and never trim a box to make a gap token measure ink instead.
- **Required:** A gap between two stacked blocks of text has to read as larger than the gap between the lines inside them, or the paragraph absorbs the heading above it. Count the leading either side of the gap, not the token alone: under a 20px card title, `--oneds-rhythm-items` reads as 22px against the 22px line-to-line of the description below it, while `--oneds-rhythm-group` would read as 18px and lose. Violation: `.card__header { gap: var(--oneds-rhythm-group); }`. Correction: `.card__header { gap: var(--oneds-rhythm-items); }`.
- **Required:** The gap under a heading is proportional to that heading, not a constant. Hold it near six tenths of the heading's cap height, so a display-scale page title steps up one rung to `--oneds-rhythm-component` while section and card titles stay at `--oneds-rhythm-items`. Violation: `.page-header__content { gap: var(--oneds-rhythm-items); }` — 12px under a 40px title reads as crowding, though the same 12px is correct under a 20px card title. Correction: `.page-header__content { gap: var(--oneds-rhythm-component); }`.
- **Required:** Prose that describes the whole section belongs in `section__header` beside the description, not as the first child of `section__body`. A paragraph placed at the top of the body is separated from the header by the section rhythm and from the examples by the component rhythm, so it groups with neither.
- **Required:** An icon set beside a block of text centres on that block; it never aligns to the top of the text box. Violation: `.dialog__body { align-items: flex-start; }` — the icon floats above the title because the box starts above the ink. Correction: `.dialog__body { align-items: center; }`.
- **Required:** Centring an icon against a label is not enough on its own. A font's line box carries more leading above the cap height than below the baseline, so the visible letters sit low inside the box and a vertically centred icon reads as floating above them. Trim the label to its cap height and alphabetic baseline so the shared centre falls on the letters: put the `text-trim` class on the text element of the pairing (the shared base rule applies `text-box: trim-both cap alphabetic` under `@supports`), give the icon `line-height: 1` so it lends no leading of its own, and keep the icon and label in one `align-items: center` row. In a grid pairing such as the alert, also give the trimmed text `align-self: center`: a grid item defaults to `align-self: stretch`, which stretches the trimmed box back up to the row height and pins the letters to the top, dropping them above the icon. Where `text-box` is unavailable the row falls back to plain centring, slightly less precise but never misaligned; because the trim removes the leading the layout was resting on, re-check the internal rhythm of any fixed pairing and widen the surrounding gap token if the trim pulled things too close. Violation: `<div class="alert__title">Heads up</div>` beside `.alert__icon`, centred but untrimmed, so the icon sits a pixel high. Correction: `<div class="alert__title text-trim">Heads up</div>` with `.alert__title { align-self: center; }`.
- **Required:** A control that pairs a leading icon with a label carries more padding on the trailing (text) side than on the leading (icon) side, because the icon's lighter optical weight makes evenly padded content read as shifted toward the text. The button steps its trailing padding up one rung, to `--oneds-component-button-icon-label-padding-inline-end` (16px) against the 12px lead. Violation: an icon-and-label button left on the symmetric `--oneds-component-button-padding-inline` on both sides, which reads as right-heavy. Correction: `.button:not(.button--icon):has(> svg:first-child) { padding-inline-end: var(--oneds-component-button-icon-label-padding-inline-end); }`.
- **Required:** One boundary has one owner. The container owns the gap between its children, so a component never sets its own outer margin. Violation: `.card + .card { margin-block-start: var(--oneds-rhythm-section); }`. Correction: `.grid { gap: var(--oneds-rhythm-section); }`.
- **Required:** Nesting descends. A container's inset is larger than the gap between its children, and the gap between siblings is at least each sibling's own inset, so a group never reads as roomier inside than the space separating it. Two exemptions: a sibling that draws its own edge (a border or a fill) is delimited by that edge and may be more generously inset, and the internal geometry of a single control is set by its component tokens rather than by this ladder. Violation: `.grid { gap: var(--oneds-rhythm-component); } .group { padding: var(--oneds-inset-loose); }` — each borderless group is padded more than the space between groups, so the groups merge. Correction: `.grid { gap: var(--oneds-rhythm-section); } .group { padding: var(--oneds-inset-default); }`.
- **Required:** Use `stack` for a column of children and `cluster` for a wrapping row, so the container carries the rhythm and unstyled children are spaced correctly by default.
- **Required:** A `separator` carries no external space. Its clearance comes from the gap of the container it sits in, which makes a separated boundary twice that gap. Do not add margin or padding to a separator; change the container's rhythm instead.
- **Required:** Body copy is constrained to `--oneds-reference-font-measure`. Specimens, tables, and component examples are exempt, since those are scanned rather than read.
- **Required:** Interface glyphs come from Fluent System Icons, addressed as `ic_fluent_{name}_{size}_{style}.svg`. Inline the SVG, keep its `viewBox`, put `fill="currentColor"` on every path, and size it with an `--oneds-reference-icon-size-*` token in CSS. Never draw a replacement glyph and never substitute an emoji, an arrow character, or a letter.
- **Required:** Fetch the Fluent asset whose grid matches the rendered size. The icon size tokens are the Fluent grids: 12, 16, 20, 24, 28, 32. Violation: a 24-grid asset rendered at `--oneds-reference-icon-size-sm`, which thins every stroke off-spec. Correction: fetch `ic_fluent_<name>_16_regular.svg` for that token.
- **Required:** Icon size follows the surface the icon sits on. Inline with text, match the text band: 12px text takes `xs`, 14px and 16px take `sm`, 20px takes `md`, 24px and larger take `lg`. Inside a square control or tile, the icon is half the container, snapped to the grid: a 32px control takes `sm`, a 40px tile takes `md`, a 48px tile takes `lg`. Leading a centred block with no container of its own, use `2xl`. Violation: a 16px glyph centred in a 40px status tile, which reads as a dot in a box. Correction: `--oneds-component-dialog-icon-size`, which resolves to `md`.
- **Required:** A component that has an icon slot sizes that icon itself, from its own token. Violation: `.empty-state__icon` with only a colour and a margin, so the glyph size depends on whatever class the page happens to add. Correction: `.empty-state__icon { width: var(--oneds-component-empty-state-icon-size); height: var(--oneds-component-empty-state-icon-size); }`.
- **Required:** Use the `regular` icon style. `filled` is reserved for a selected, current, or active item and for a status glyph whose meaning is the point. Never mix the two styles inside one control group.
- **Required:** Give a decorative icon `aria-hidden="true"`, and give an icon-only control an `aria-label` naming the action. A status icon never carries the meaning alone; the status stays in text as well.
- **Required:** Fetch site favicons from Google's favicon service with an encoded host and `sz` set to the first power of two at or above twice the rendered size. Render into the `--oneds-component-favicon-*` box, request with `loading="lazy"`, `decoding="async"`, and `referrerpolicy="no-referrer"`, and fall back to the Fluent `globe` glyph when the request fails.
- **Required:** `tokens.css` is generated by `scripts/build-tokens.mjs`. Never edit it directly. Colour theme changes go in `tokens/theme.json`; status colours and all non-colour tokens go in `tokens/oneds.tokens.json`. Either way, rebuild afterwards.
- **Required:** Put all CSS in output HTML inside an inline `<style>` block.
- **Required:** Build unmatched UI in `src/_local/` and identify it with `ONEDS-CANDIDATE: name, what it was for`.
- **Forbidden:** Invent color, spacing, or size values.
- **Forbidden:** Reference `--oneds-reference-space-*` from generated UI. The primitive ladder is private and exists only for rhythm, inset, and component tokens to resolve against. Violation: `.panel { padding: var(--oneds-reference-space-16); }`. Correction: `.panel { padding: var(--oneds-inset-default); }`.
- **Forbidden:** Use a spacing token for anything that is not space. A control height, an icon size, a blur radius, or a column width is a size and has its own token. Violation: `.avatar { width: var(--oneds-rhythm-page); }`. Correction: `.avatar { width: var(--oneds-reference-control-height-lg); }`.
- **Forbidden:** Write `0` as a token. Zero is the absence of spacing, so write the literal `0`.
- **Forbidden:** Wrapping CSS keywords in custom properties. Tokens exist for values that could be themed: color, spacing, size, radius, duration, shadow, font. Layout keywords such as display, position, flex-wrap, justify-content, align-items, and border-style are written as literals.
- **Forbidden:** Set `width` or `height` on an icon `<svg>`, or paint one with a colour token. Size comes from an icon size token in CSS; colour comes from `currentColor` on the surrounding text.
- **Forbidden:** Rewrite or fork a matching OneDS component.
- **Forbidden:** Include external stylesheet links, script references, or CSS imports in output HTML. This covers the code a page needs in order to render itself; a remote image fetched at request time, such as a favicon, is not covered.
- **Forbidden:** A `<table>` whose nearest wrapper does not set `overflow-x: auto`, including a table placed directly in page flow or straight into a `.card` with no scroll wrapper.
