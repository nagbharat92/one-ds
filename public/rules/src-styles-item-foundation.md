### List Items use shared full and compact anatomy

composition.list-item | Required | approved | enforcement: Partially automated

Build list rows from Item and its named parts; do not restyle Item geometry or interaction states in consumers. Standard Items use a 26px outer radius, 16px inset, and 10px nested radius. Use the compact prop for intentional title-only rows: compact Items are 40px high with a 20px outer radius and 6px inset; their 28px media and action hosts use a 14px radius and 16px graphic. A direct 32px edit field in a compact Item uses a 4px inset and 16px radius, preserving the 40px row and concentric geometry. ItemTitle fades overflowing text at its trailing edge instead of an ellipsis. ItemActions hosted automatically applies compact geometry and sits on an opaque host-matched background. Its action fades in on fine-pointer hover, remains keyboard-focusable and appears on focus, and stays visible on coarse/touch input. Pair a selectable row with ItemPrimaryAction and keep ItemActions hosted as its sibling, never nest one button inside another. Use ItemMedia variant=icon for the circular media host, variant=image for the 44px image with the standard 10px inner radius, and ItemActionSlot for a mirrored transparent trailing graphic host. The muted variant is the selected Item state and uses the shared Secondary purple fill and paired ink. Interactive list rows use the same state-layer color and hover, focus, and pressed opacity tokens as Ghost Button. Resolve those layers over each row's actual resting host so default, outline, selected, and hosted rows preserve their base surface and hosted action masks match the visible row fill. Navigation pane menu and submenu rows consume the same Item state composites. Product navigation without NavigationPane-specific icon, collapse, or tooltip behavior composes Item compact with ItemContent and ItemTitle directly. Item has no generic size axis; compact is the only alternate composition.

Exceptions: Avatar and circular icon media are centered fixed circles, so they are floating graphics rather than uniformly inset rounded surfaces; the concentric corner equation applies to the Item boundary and nested corner-aligned surfaces. A descriptive hosted Item grows with its description and preserves the 16px text inset below it. ItemGroup controls spacing between peer rows, and product data or selection orchestration remains local.

### Menus share one expressive grouped treatment

composition.expressive-menu | Required | approved | enforcement: Partially automated

The Dropdown, Context, and Menubar families share one Material 3 Expressive grouped treatment by default. Ordinary direct or mixed children are normalized by MenuContent into one implicit raised chunk; content composed only from explicit MenuGroup children preserves one or two authored chunks. Consumers may pass grouped={false} only to request the baseline shadcn treatment. All three consume the shared menu module and the --menu-* tokens; never fork the class strings, child normalization, press behavior, or token names per component. Select, Combobox, and Navigation Menu preserve their own listbox or navigation semantics, but their floating surfaces, item rows, labels, dividers, and interaction fills consume the same --menu-* visual tokens. Grouped command-menu content is a transparent shell with no surface of its own: each explicit or implicit group renders a raised white chunk on the floating elevation plus the shared --elevation-stroke hairline, and chunks stack with the 4px --menu-chunk-gap. A command menu carries at most two chunks; a longer or scrolling menu keeps one chunk and separates sections with padded dividers inset by --menu-divider-margin-inline, never edge to edge. Rows are at least 40px (--menu-item-height) with concentric corners: the inner radius is --menu-item-inner-radius, only the first and last rows round the chunk edge with --menu-item-edge-radius, and --menu-chunk-radius equals the edge radius plus the chunk padding. Interaction uses the warm tertiary state layer over the white surface: hover is --menu-item-hover-fill (8%), focus is --menu-item-focus-fill (10%), and press is the darker --menu-item-pressed-fill (16%) driven by a transient data-pressed pointer state and :active where the primitive allows it, so holding a row reads darker than hovering it. Selection is shown by the check mark alone; there is no filled selected row. An open submenu trigger changes color only and never morphs its corner radius, and a grouped submenu inherits the treatment through the shared context and opens with an 8px offset so its gap matches the chunk gap. Row text is wrapped with IconLabel where children are freeform and carries an 8px trailing pad; a title is a muted 40px row that aligns to the icon column when inset. A title flows directly into its first option: a separator immediately following a title is suppressed, while later dividers still separate sections. Non-interactive identity content is a title inside its related chunk rather than its own chunk. Keep every value tokenized: no raw lengths, colors, or arbitrary utilities in menu styling.

Exceptions: The baseline shadcn command-menu surface remains available only through grouped={false}; new consumers do not need to opt into the expressive treatment. Select and Combobox do not get grouped chunks or the two-chunk rule because they are listboxes; they only inherit the shared visual row and surface language. Navigation Menu is navigation, not a command menu, so it uses the same floating surface and row-state tokens without MenuGroup chunking. Menubar and Context checkbox and radio rows use the shared right-hand indicator for consistency. Material notes grouped gaps are not for scrollable menus, so a scrolling menu uses dividers inside one implicit or explicit chunk instead of extra chunks.
